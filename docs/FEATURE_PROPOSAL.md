# InkRidge 功能建议

> 基于对 `Assets/Scripts`（29 个文件 / 3089 行）与 4 个场景 `.unity` 文件的实际通读。
> 所有结论都附了文件与行号，可复核。

## 一句话结论

**先别急着加功能——冥想核心回路有两条感官通道是黑的，而且设置面板在 Quest 上根本打不开。**
这两件事修完，体验提升会大于后面任何一项新功能。

---

## 第一部分：现状核实（不是建议，是必须先知道的）

### 1. 呼吸音效完全没接上

- `Assets/Scripts/Environment/BreathAudioSync.cs` 的 `OnPhaseChanged()` 在**全项目零调用点**——这是个死组件。
- 四个场景里 `MeditationPoint._breathAudioSource` 与 `_ambientAudioSource` 全是 `{fileID: 0}`（未赋值）。
- `MeditationPoint.StartMeditation()`（:111）确实会 `_ambientAudioSource.Play()`，但字段是 null，所以**环境音在冥想期间也不会响**。

结论：冥想时只有光圈和粒子，听觉全程静默。对一个"呼吸引导"应用来说，这是核心回路缺了一半。

### 2. 设置面板在真机上打不开

`Assets/Scripts/UI/XRMenu.cs:47` 用 `Input.GetKeyDown(KeyCode.M)` 开关菜单。
Quest 没有物理键盘。项目 `activeInputHandler=2`（纯 Input System），legacy Input 根本不触发——
`StartGate.cs:66` 的注释里自己写明了这一点，但 XRMenu 没跟上。

玩家在头显里无法改移动速度、转身角度、晕影、坐站模式。

### 3. 「呼吸稳定度」是一个恒为 1.0 的假指标

`BreathGuide.RecordCycleDuration()`（:131）算的是**静态表** `PatternTimings` 里几个常量的和，
不是实测的周期时长。方差恒为 0 → `GetRhythmStability()`（:144）恒返回 1.0。
这个值被写进 `BreathData`、存进存档、显示在结算页（:49）的「呼吸稳定度: 100%」。

所有用户都会看到 100%。要么修成实测，要么从 UI 上撤掉——现在这样是在骗用户。

### 4. 结算页「本次步行」显示的是累计值

`SummaryScreen.cs:46` 与 `:52` 用的是同一个 `save.totalWalkingTime`。
两个标签一个写「本次步行」一个写「累计步行」，显示的却是同一个数。
根因：`SaveManager` 只维护累计值，从来没有 per-session 的步行计时。

### 5. `Pattern.Free` 名不副实

README 写「🌙 山顶星空 / 释然 / 深长自由呼吸」，但 `PatternTimings[3]` 是固定的 `{6, 2, 8, 0}`，
和前三个模式一样是定时器驱动。所谓"自由"只是节奏不同，并不跟随用户的呼吸。

### 6. README 声称的 22 个测试不存在

`Assets/Tests/` 是**空目录**。`AGENTS.md` 里写的 `BreathGuideTests.cs` /
`ComfortSettingsTests.cs` / `SaveManagerTests.cs` 三个文件都没有。
根目录还留着一个指向空目录的 `Tests.csproj`。

### 7. 两个次要项

- `ComfortSettings` 全程 `PlayerPrefs.SetXxx` 但**从不调 `PlayerPrefs.Save()`**。Quest 会激进地杀后台，设置可能丢失。
- `MeditationPoint._breathCircleTransform`（:24）已声明但代码中从未使用，且四个场景里都是 `{fileID: 0}`。死字段。

## 第二部分：新功能建议（按优先级）

### P0 — 投入小、直接决定核心体验能不能成立

| # | 功能 | 为什么 | 大致工作量 |
|---|---|---|---|
| 1 | **呼吸触觉反馈** | 全项目 `grep Haptic\|Impulse\|vibrat` 零命中。VR 冥想里触觉是最被低估的通道：每个相位切换给一次轻脉冲，用户**闭着眼也能跟上节奏**，不必死盯光圈。这能把"看引导"变成"感受引导"，是本项目最划算的一项 | 小（相位切换时 `SendHapticImpulse(0, 0.15f, 0.08f)`，吸气/呼气用不同振幅） |
| 2 | **接上呼吸音效** | 见第一部分 #1。不是新功能，是把已有的 `BreathAudioSync` 接对：在 `BreathGuide` 里加相位切换事件，`MeditationPoint` 订阅并转发 | 小（组件已写好，缺的是事件与接线） |
| 3 | **冥想中途可退出** | 现在 180s 一旦开始无法中断。VR 里这是硬伤：不适、有人进门、想调整姿势，全都没有出路。玩家需要能随时按手柄键退出并保留已完成部分 | 中（退出确认 + 部分进度落盘 + `BreathData` 加 `completedEarly` 标记） |
| 4 | **凝视确认的进度反馈** | `StartGate` 做了进度条（:142-162），`MeditationPoint` 的 3 秒凝视确认**没有任何视觉提示**。玩家不知道要盯着别动，只会以为卡住了 | 小（把 StartGate 的进度条逻辑抽成共用组件） |
| 5 | **XRMenu 改为手柄按键** | 见第一部分 #2。改用 Input System 的 `MenuButton`（Quest 左手菜单键），并接上 XR 射线交互 | 中（还要补 `TrackedDeviceGraphicRaycaster` + 手柄 Ray Interactor） |

### P1 — 决定这是个 demo 还是个产品

| # | 功能 | 为什么 |
|---|---|---|
| 6 | **真的自由呼吸模式** | 让 Summit 的"自由呼吸"变成真的：开局标定一次（吸气→屏息→呼气各按一次手柄），之后按用户自己的实际周期走，引导者跟随用户而不是用户跟随定时器。同时这才是 `GetRhythmStability()` 唯一有意义的场景——有了实测周期，稳定度才是真数据 |
| 7 | **连续记录 / 打卡** | `BreathData.timeStampISO` 有 UTC 时间戳但**完全没被用过**。没有 streak、没有日历、没有历史回顾。冥想类产品的复购基本靠这个抓手，现在等于白存了数据。建议：连续天数、本周热力图、历史总览 |
| 8 | **传送移动 + 舒适档位** | 只有 smooth move + snap turn，对晕动敏感的用户没有退路。加 `TeleportationProvider`，并在设置里给"舒适 / 标准 / 自由"三档预设（一键配置移动方式+晕影+速度）而不是现在这样四个互不相干的滑杆 |
| 9 | **中文显示** | 项目主题是水墨山水，但 `Assets` 下**没有任何字体资源**，`StartGate` 只能显示英文（`LegacyRuntime.ttf` 无 CJK 字形）。需要一个 TMP 中文字体资产（思源黑体子集化，只保留 UI 用字可以压到 2-3MB） |
| 10 | **身高校准** | `ComfortSettings.ApplySeatedMode()` 硬编码 0.8m / 1.75m。跟用户实际身高不匹配时整个场景的尺度感都是错的。Quest 能读到用户设置的身高，加一个"自动 / 手动微调"即可 |

### P2 — 打磨

| # | 功能 | 为什么 |
|---|---|---|
| 11 | **场景加载进度** | 所有几何体是运行时生成的（每个场景几百个 primitive），切场景时可能黑屏数秒且无任何反馈。`SceneTransition` 已经有 `CanvasGroup`，加个进度条或直接显示 `op.progress` 即可 |
| 12 | **脚步声修正** | `LocomotionController.Update()` 只轮询 `leftHandMoveInput`——用右手摇杆移动时没有脚步声；且步长固定 0.8s 不随移动速度变化；单一 clip 无随机音高，连走会有机关枪感 |
| 13 | **呼吸难度递进** | 四个场景的呼吸法是硬编码在场景里的（`_pattern: 0/1/2/3`）。可以做成一个随完成次数渐进的课程：新手 4-4-4，熟练后 4-7-8 → 箱式 → 自由呼吸，让重复游玩有目标 |
| 14 | **环境音分层** | 冥想进行中随深度渐入一层低频 drone 或钟磬，`AudioMixerController` 已经有 `_meditationAmbientDip` 的骨架，但那个 lerp 结果目前没人读 |

### P3 — 产品层

- **冥想后情绪记录**：结束后三档简单自评（浮躁 / 平静 / 澄明），存进 `BreathData`，与呼吸数据关联，长期看趋势
- **时辰 / 四季变化**：同一个场景按真实时间渲染晨昏，或按季节换配色（工笔画的留白很吃这套）
- **引导语音**：真人录制的中文引导词，比纯视觉引导的沉浸感强一个量级
- **同修模式**：多人共享同一处冥想点，能看到彼此的呼吸光晕（不打扰，只是"有人在"）

## 建议的推进顺序

1. **第一批（止血）**：#2 呼吸音效接线 + #1 触觉 + #4 凝视进度 + #5 XRMenu 手柄化
   → 这四项做完，核心回路的四个通道（视觉/听觉/触觉/交互）就全通了
2. **第二批（立住）**：#3 中途退出 + #6 真自由呼吸 + 把 #3 实测周期接到 #4 稳定度上，同时修 #3§3 和 #4§4 两个假数据
3. **第三批（留人）**：#7 连续记录 + #8 舒适档位 + #9 中文 + #10 身高校准

第 1、2 批大约能让这个应用的完成度有质变；第 3 批决定它能不能留住人。

---

## 附：几个我刻意没建议的

- **更多场景**：4 个场景的几何体已经很扎实，加新场景的边际收益远低于把现有冥想回路做完整
- **社交 / 排行榜**：与"冥想"这个主题的气质冲突，且会引入审核与隐私成本（`PRIVACY_POLICY.md` 已经写了不收集数据）
- **程序化生成关卡**：运行时建几何体已经是这个项目的性能负担之一，再叠加生成逻辑会拖慢切场景
